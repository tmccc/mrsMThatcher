Summary Verdict
---------------

I do not see a remaining correctness blocker in the generated-image pool
implementation.

The implementation is deliberately guarded:

- generated image pool is default-off;
- existing original image pool behaviour is unchanged while disabled;
- generated image files remain in generated_review_approved_images/;
- generated image analysis remains in generated_image_analysis.json;
- live images/ and live image_analysis.json are not modified;
- generated images are normal scoring candidates, not forced by quote hash;
- originating quote hash gives only a small configurable boost;
- stale, missing, out-of-season, or strong-mismatch images are handled by the
  existing image metadata checks;
- legacy integer image history is not destructively migrated while the generated
  pool is enabled.


Issues Found And Fixed During Review
------------------------------------

1. Manifest was staged but not used by runtime

The generated staging manifest:

    generated_review_approved_images/manifest.json

is useful provenance, but mrsMThatcher2.py does not read it. Runtime requires:

    generated_image_analysis.json
    generated_review_approved_images/tg_<quote_hash>.png

I unstaged manifest.json so it remains unversioned.


2. Generated glob traversal guard

The first implementation accepted GENERATED_IMAGE_GLOB directly. A bad local
config such as:

    GENERATED_IMAGE_GLOB = "../outside/*.png"

could make current_image_paths() see files outside GENERATED_IMAGE_DIR.

Fix:

    current_image_paths() now checks each generated image with
    path_is_same_or_child(image_path, generated_dir) and skips anything outside
    the configured generated-image directory.

Added test:

    test_generated_image_pool_rejects_paths_outside_generated_directory

Residual Limitations
--------------------

1. No generated-image frequency cap yet

Generated images compete normally with original images once enabled, with only
the origin-quote boost. If generated images visually dominate, a later change
could add a generated-share cap. I did not add one here because it would alter
selection policy more broadly.


2. Generated-pool fallback on missing generated analysis

If ENABLE_GENERATED_IMAGE_POOL is true but generated_image_analysis.json is
missing or invalid, load_image_analysis() logs a warning and uses only the
original image pool.

This is operationally safe and avoids taking the whole regular post lane down
because the optional pool is unavailable. It also means a misconfigured generated
pool silently degrades to the original image pool except for warning logs.


3. Basename identity remains global

Image used history remains basename-based. This is safe with current generated
filenames because they are tg_<quote_hash>.png and do not collide with tNN.jpg.
The implementation also skips generated images whose basename collides with a
primary image.


4. Generated metadata is merged in memory only

The live image_analysis.json is not modified. This is intentional and supports
clean rollback by disabling ENABLE_GENERATED_IMAGE_POOL.
